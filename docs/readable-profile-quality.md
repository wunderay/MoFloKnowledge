# Readable company profile: requirements and baseline evaluation

This document defines acceptance for the readable-profile milestone. It complements [the no-AI redesign](no-ai-redesign.md): extraction remains deterministic, exact-source, and non-generative. Account-it evidence was checked on 2026-10-16 against the previous capped product run and separately fetched first-party pages. The evidence decisions below keep those sets separate: a fact present on the website is not evidence that a product run captured it.

## Recommendation

Keep extraction deterministic and evidence-first. Select complete original sentences or headings by source role and exact field fit; prefer company-level overview passages for the company overview, service-page passages for offerings, and the named bio for person claims. Drop navigation repetition, non-content article fragments, and duplicate sentences. Preserve source order for similarly ranked passages. Do not synthesize connective prose. Every selected value retains the exact source excerpt, source URL, page identity, and retrieval/capture status; the full passage remains available when a concise preview is shown.

For selection, relevance and novelty are useful separate considerations: the original MMR work combines query relevance with information novelty to reduce redundant passages. A small deterministic page-role/heading score plus exact or normalized duplicate checks is sufficient here; do not introduce learned similarity or an external model. [Carbonell & Goldstein, SIGIR 1998](https://www.cs.cmu.edu/afs/cs/Web/People/jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf)

Model evidence as a relation among a source page, an exact segment, the extraction activity/version, and the proposed field. The current app already retains immutable evidence and revisions, so this is a presentation/selection contract, not a request for a provenance schema migration. The W3C Web Annotation model supports targeting an exact text quote with context on a web resource; PROV-DM describes source entities, activities, derivations, and responsibility. [Web Annotation Data Model](https://www.w3.org/TR/annotation-model/), [PROV-DM](https://www.w3.org/TR/prov-dm/)

Present the profile with a short descriptive overview, grouped field sections, meaningful headings, and explicit unknown/partial/not-checked reasons. Keep full evidence and long source passages available without forcing every paragraph into the first screen. WCAG 2.2 calls for structure and relationships to be programmatically available or present in text, and a meaningful reading sequence; its heading guidance supports a section hierarchy that users can scan. [WCAG 2.2, 1.3.1 and 1.3.2](https://www.w3.org/TR/WCAG22/)

## Whole-profile acceptance checks

These checks assess the user’s task and source alignment, not output word count, proposal count, a hand-picked claim fraction, or baseline similarity.

- A reviewer can use the profile to answer: what does the company do, who does it explicitly serve, what are the named services, how do I contact or schedule, and which requested baseline details are unknown or not captured? Each answer is directly supported by a nearby source link and exact excerpt.
- Every baseline field and distinct assertion below has one of: (a) a matching, applicable source passage and a semantically compatible profile field; (b) a precise unknown/not-checked/partial reason; or (c) an explicit conflict. No supplied-baseline wording becomes runtime data solely because it appears in that baseline.
- Overview passages are exact, relevant company-level source sentences; no menu dump, repeated page links, generic filler, founder biography, or unsupported summary remains in the default overview. Every sentence can be traced to the correct captured page and selection reason. All omitted full source content remains inspectable from the source record.
- Offering names and parent/child relationships follow published page hierarchy. Descriptions contain relevant exact passages from the matching detail page; features are distinct named list items or directly relevant source segments, not entire repeated descriptions. A named child with no detail remains name + parent + “details not found in captured source”; sibling content is never borrowed.
- Buyer labels are normalized for duplicate spelling/plural variants while preserving the source wording and context. “Customer need” is reserved for explicit problems, goals, or requested outcomes; promotional claims and educational/article text remain source passages in their proper sections. Persona output is a sourced audience profile, never an invented person or persona; if the source only states audience groups, show groups rather than fabricating persona fields.
- Contact mechanisms distinguish observed links, visible forms, fields, and destinations from a completed user journey. A link/form is not a funnel stage; only source-declared transitions may be represented as a funnel. Form purpose is unknown unless the nearby heading/copy explicitly states it. Completion or conversion is never inferred from control labels.
- Source coverage distinguishes captured, selected, failed/blocked, linked but not selected, and not discovered. An unselected page is not “not found.” Report the capture limit and outstanding high-priority linked pages so the user can tell unknown from absent.
- Unknown/unsupported values stay visible with a reason and an action such as “not stated in captured pages” or “linked page not captured.” Known technical observations (CSS fonts/colors, declared logo URL, forms/links) remain observations; they do not become brand standards, supplier relationships, verified assets, gender, or demographics.
- At desktop and a 390-pixel mobile viewport, the profile has a readable single-column path, scan-friendly section headings, labelled facts/lists, accessible navigation/expand controls, and no raw JSON/nested `Text`/`Id`/`Raw` presentation. Long passage preview has a clear full-text action; source excerpt and page link stay available. Empty section state identifies why it is empty rather than silently displaying blank arrays.
- Before/after evaluation uses the same captured source snapshot, profile state, viewport sizes, and task script. Record task completion and wrong/unsupported answers for the representative tasks above, then compare old and new. A change passes only when task answers become easier to locate without losing source access or introducing unsupported values. Supplement this with the complete field-by-field baseline traceability matrix below and focused generic fixtures for ambiguous dates, unsupported persona attributes, duplicate passages, linked-but-uncaptured pages, and nested service hierarchy.

### Representative before/after review tasks

Use the same saved profile and capture snapshot for both versions. For each task, the reviewer must give the answer and open its supporting source without resorting to raw JSON or an external search. A task fails if the answer is absent from the profile, appears under a misleading field, lacks an applicable citation, or overstates what the source shows.

1. Identify the exact company name, office location, and one-sentence company description; open each cited page.
2. Find the explicit individual-tax audience and small-business size range. State whether the range describes Account-it's own employee count or its customers.
3. Find the QuickBooks service and training/QuickAnswers details; distinguish the offering page from the company-level QuickBooks Online statement.
4. Find the tax preparation/planning children and parent; tell whether “Trust” is present on the page that supplies each label.
5. Locate contact, appointment, email-article signup, and referrals entry points. State which are observed links/forms and whether any completed appointment/signup was observed.
6. Explain why the requested gender, supplier list, style diagnosis, exact baseline logo candidate, and LLC formation year remain unknown or qualified.

Run the script on desktop and mobile with keyboard navigation as well as pointer interaction. Record each answer, cited source, wrong inference, and interaction that was hard to find. Compare the records before and after; do not reduce the result to an arbitrary percentage or word count.
