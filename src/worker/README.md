# Durable worker

Run `npm run worker` as an independent persistent Node 22 process. Configure `WORKER_DATABASE_URL` for a dedicated PostgreSQL login granted only the `moflo_worker` group. It must not own tables or have direct table access. Web operations use the authenticated caller's Supabase JWT and never this connection.

The worker claims one job, renews its 60-second lease every 15 seconds, and passes company/job/token to every protected write. A lost lease aborts work and prevents a terminal write by the superseded attempt. SIGTERM/SIGINT stop network/model work; an unfinished lease can be reclaimed. Claims supply immutable source captures and current entry summaries transiently. Checkpoints contain the frontier, consumed budgets, safe errors, completed source IDs and compact validated candidates; source bodies remain in source rows.

HTTP/renderer work uses the network lane's pinned public-address transport, robots cache, normalized frontier and bounded scheduler. A rendered capture is finalized before source insertion. Missing renderer configuration preserves honest partial coverage. Production browser isolation requires the renderer qualification report described in `src/renderer/README.md`.

`OPENAI_API_KEY` and `OPENAI_EXTRACTION_MODEL` enable per-page Responses API Structured Outputs. The schema is derived from all 41 registry fields and removes UUIDs; trusted code assigns stable identities. The prompt supplies sanitized text and captured observations as untrusted data without tools. Local validation checks typed values, observed URLs, captured segment/observation IDs and special employee/pricing/gender/legal/story rules. Reduction merges identical evidence, unions separately identified collection items, and retains conflicting scalar candidates for review. Generated suggestions keep explicit supporting claim dependencies across the batch.

No model/provider is configured or qualified by this code. Recorded illustrative responses prove deterministic parsing/reduction behavior; they do not prove a live model's accuracy or schema support. Without a model, deterministic website/style/social observations remain available and unassessed fields retain partial coverage. The job allows at most 120,000 model tokens (conservative estimates when usage is unavailable), 12,000 output tokens per call and the remaining five-minute job deadline. Refusals, invalid citations, truncation, timeouts and checkpoint-budget limits produce safe errors and partial results.

Finalization is a protected SQL transaction: an empty company receives unreviewed entries once; any existing human draft makes the job proposal-only. Publication remains an explicit member review operation. Saved snapshots never depend on current worker state.
